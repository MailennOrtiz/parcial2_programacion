17CHECK constraints — el garante que no depende de quién escribe

Esta comparación no tiene botón. El problema no es una forma alternativa de escribir el alta: es que cualquier otra puerta además de la API (un script, alguien con psql) puede esquivar por completo la validación de Pydantic. La demo real se hace fuera de esta página, por consola/psql, directo contra la base.

modules/productos/models.py 
__table_args__ = (
    CheckConstraint("precio > 0", name="ck_producto_precio_positivo"),
    CheckConstraint("costo_interno >= 0", name="ck_producto_costo_no_negativo"),
)

Resultado real, probado directo en psql, sin pasar por la API:

UPDATE producto SET precio = -5 WHERE id = 1;
ERROR:  el nuevo registro para la relación «producto» viola la restricción
        «ck_producto_precio_positivo»

Rechazado igual, aunque la API ni se haya enterado de que alguien lo intentó.
